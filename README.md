# Разметка одежды по изображениям

Чтобы искать похожие товары и рекомендовать подходящие дополнения, каталогу одежды нужны единообразные данные: что изображено на фото, какого цвета вещь, есть ли рисунок и какие другие визуальные признаки у нее присутствуют. Описания разных магазинов отличаются по формату и полноте, а ручное заполнение характеристик трудоемко. Задание предлагает получать структурированную разметку непосредственно по фотографиям с помощью готовых CV-моделей и мультимодальных подходов.

Единый словарь такой разметки задает таксономия — категории одежды, применимые к ним атрибуты и допустимые значения. Здесь используется сокращенная версия Ximilar Fashion Taxonomy (https://docs.ximilar.com/taxonomy/fashion). Модель распознает предмет и его признаки, а микросервис сопоставляет результат с таксономией, проверяет корректность ответа, явно обозначает неизвестные характеристики и сохраняет данные в PostgreSQL. Такая разметка станет основой для последующего поиска и рекомендаций. Задача этой работы — сравнить три подхода через API, выбрать один и реализовать надежный путь от получения изображения одежды из S3-совместимого хранилища до записи описанных характеристик в БД.

**Ориентир: 10–12 часов**, включая знакомство с материалами, эксперименты, реализацию, тесты и видеоотчет. Модели используются через API, GPU не требуется. На эксперименты могут быть предоставлены ключи с бюджетом $10–20, доступы передаются отдельно по запросу в лс.

## Что подготовлено для дальнейшей реализации

- FastAPI с одной бизнес-ручкой `POST /annotate`, подключением к PostgreSQL и таблицей с JSONB.
- Docker Compose, проверка готовности БД, тесты инфраструктуры и workflow CI без платных API.
- Сокращенная [таксономия](data/taxonomy/clothing-v1.json), описание данных, подходов, метрик и требований к результату.

Один запрос содержит **1–N фотографий одного товара и цветового варианта**; ответ и запись в БД содержат одну объединенную разметку. В каркасе N задается `MAX_IMAGES_PER_ITEM`, по умолчанию 5. Фотографии из S3 можно скачать клиентом и передать сервису файлами.

Разметка, подготовка изображения для конкретной модели, вызовы моделей, расчет метрик, score и сохранение результата — ваша часть работы. Готовых реализаций этих шагов здесь нет. Исходные изображения и контрольные значения из карточек магазинов были подготовлены и загружены в Object Storage от Yandex Cloud, поэтому собирать или размечать датасет в рамках задания не требуется.

## Быстрый запуск

Нужны Git и работающий Docker с Compose. Из терминала:

```bash
git clone https://github.com/ShvDanil/clothes-tagging-lab.git
cd clothes-tagging-lab
git switch -c feat/clothes-tagging
cp .env.example .env
docker compose up --build -d --wait
curl --fail http://localhost:8000/health
curl --fail http://localhost:8000/ready
```

Обе проверки должны вернуть HTTP 200. Документация API: [localhost:8000/docs](http://localhost:8000/docs). PostgreSQL доступен на `localhost:5433`; внутри Compose API обращается к `db:5432`.

Отправка одного или нескольких ракурсов (для одного фото оставьте один `-F`):

```bash
curl -i \
  -F 'images=@/absolute/path/to/front.jpg' \
  -F 'images=@/absolute/path/to/back.jpg' \
  http://localhost:8000/annotate
```

В исходном каркасе эта ручка возвращает **HTTP 501**: реализация находится в [app/service.py](app/service.py). Это ожидаемое состояние заготовки. После выполнения задания ручка должна объединять сведения из переданных ракурсов и сохранять одну разметку товара в БД. Имена полей и структура ответа выбираются вами.

Тесты PostgreSQL через Docker, без локального Python и ключей моделей:

```bash
docker compose --profile test build tests
docker compose --profile test run --rm tests
```

Остановка с сохранением данных: `docker compose down`. Команда `docker compose down -v` удаляет локальную БД этого проекта; используйте ее только для намеренного сброса.

## Что делать далее

Сначала прочитайте документы из раздела «Навигация» ниже в порядке строк таблицы — от «Задания» до «Сдачи». Затем переходите к выполнению:

1. Сравнить три подхода на общей validation/test-разбивке: качество, задержки, ошибки и стоимость. Результаты и воспроизводимый способ сравнения сохранить в репозитории, например, в папку experiments.
2. Выбрать один подход и реализовать для него полный путь от загруженного изображения до записи в PostgreSQL. Объяснить и обосновать выбор.
3. Продумать уверенность отдельных предсказаний и общий score пайплайна, неизвестные признаки и необходимость проверки.
4. Обработать нештатные ситуации, добавить автоматические тесты и сохранить работоспособность CI.
5. Заполнить [REPORT.md](REPORT.md), запушить решение в `feat/clothes-tagging`, отправить видео до 4 минут в Telegram организатору вместе со ссылкой на ветку и хешем коммита.

Полноценный сервис нужен для одного подхода. Возможность переключения реализаций допустима, способ организации кода остается на ваше усмотрение. Обучение моделей, интерфейс каталога и система рекомендаций не входят в объем задания.
