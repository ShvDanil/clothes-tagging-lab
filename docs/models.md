# Направления для сравнения

Сравните три различных подхода. Ниже — рекомендуемый набор; один из вариантов можно заменить собственным пайплайном, объяснив его отличие и мотивацию. Необходимо получить сопоставимую разметку категории и основных атрибутов.

## 1. Генеративная мультимодальная модель

Передача фотографии и описания задачи VLM через API с последующей проверкой результата по таксономии. Можно использовать провайдера с поддержкой изображений напрямую или через OpenRouter. Выбор модели, инструкции, ограничение формата и разбор ответа — ваша часть работы.

Проверьте поддержку изображений и структурированного вывода именно у выбранной модели. Запишите точный идентификатор, параметры, дату и стоимость. Старые примеры и лимиты провайдеров могут измениться.

- [Каталог OpenRouter с фильтром image input](https://openrouter.ai/models?fmt=cards&input_modalities=image)
- [Документация OpenRouter](https://openrouter.ai/docs)

## 2. Классификация Jev / TypeSafe

Используйте `Choice` для выбора среди допустимых категорий/значений. Отдельно продумайте неизвестный или отсутствующий в таксономии вариант: выбор максимума среди известных классов не доказывает, что товар относится к одному из них.

На 07.11.2026 поддержка изображений у TypeSafe экспериментальная. Официальные инструкции требуют заголовок `TypeSafe-Danger-Zone-Images: true`; поддерживаются JPEG/PNG с ограничениями размеров. Перед реализацией сверьте актуальный контракт и доступную версию Jev. Эти требования провайдера не являются готовой реализацией подготовки изображения.

- [Изображения: формат запроса и ограничения](https://docs.typesafe.ai/images)
- [Choice: варианты и вероятности](https://docs.typesafe.ai/primitives/choice)
- [Смысл confidence](https://docs.typesafe.ai/confidence)

Если экспериментальный API недоступен с выданным ключом, согласуйте замену этого подхода до итогового прогона. Не предполагайте, что один ключ автоматически открывает доступ ко всем провайдерам.

## 3. Мультимодальные embeddings

Один из вариантов — API `jina-clip-v2`: сопоставление представления изображения с текстовыми описаниями допустимых классов/признаков. Самостоятельно определите тексты классов, процедуру сравнения, обработку неоднозначности и способ получения атрибутов.

- [Карточка jina-clip-v2 и доступные способы использования](https://jina.ai/models/jina-clip-v2/)
- [Jina Embeddings API](https://jina.ai/embeddings/)

Используйте API, локальный запуск весов и GPU не требуются. Косинусное сходство не является вероятностью правильного ответа. Условия использования API и лицензия весов — разные вещи; соблюдайте условия выбранного способа доступа.

## Доступы и бюджет

Организатор отдельно может выдать ключи с общим лимитом $10–20 на эксперименты. Перед большим прогоном проверьте доступность всех трех подходов и оцените стоимость с учетом числа изображений, запросов на товар и повторных попыток. Учтите, что общий бюджет может быть распределен между несколькими аккаунтами провайдеров.

Сохраните повторно используемые результаты запросов для воспроизведения анализа; не отправляйте одни и те же изображения заново без необходимости. Исходные ответы, содержащие изображения или доступы, храните локально в игнорируемой папке. В репозитории должны остаться безопасные результаты экспериментов и код их воспроизведения.

Для выбранного production-подхода укажите, как задать ключ и модель в `.env` и передать их в контейнер. CI использует подмены провайдера и не расходует бюджет. Три готовых production-адаптера от вас не требуются.
