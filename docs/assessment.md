# Критерии приемки

Результат оценивается по воспроизводимости решения и обоснованности выбора, а не по сложности архитектуры. В отчете приведите доказательства по пунктам ниже.

| Область | Ожидаемый результат |
| --- | --- |
| Запуск | Из чистого клона по инструкции поднимаются API и PostgreSQL через Compose; зависимости и необходимые переменные зафиксированы. |
| Эксперименты | Сопоставлены три подхода на одном выданном test, сохранены предсказания, качество, время, стоимость и конфигурации. Все пропуски/ошибки учтены; выбор подхода, который будет в бизнес-логике объяснен. |
| Разметка | Одна бизнес-ручка принимает 1–N фото одного товара, объединяет сведения и возвращает категорию/атрибуты из словаря с явной неопределенностью. В README/OpenAPI описан ваш формат результата. |
| Надежность результата | Есть объяснимые оценки отдельных предсказаний и общий score, покрытие и правило проверки. Ограничения confidence сформулированы, пороги выбраны без настройки на test. |
| PostgreSQL | Результат и сведения о его происхождении сохраняются, транзакции и повторы не оставляют некорректных или дублирующих записей. |
| Сбои | Обработаны лимиты входа, недоступность/таймауты модели, конечные повторы, невалидная/частичная разметка и ошибка записи в БД. Поведение описано и проверено. |
| Тесты и CI | Автоматически проверяются штатный путь и существенные ошибочные сценарии, включая сохранение и повтор запроса. В CI нет платных вызовов и секретов. |
| Сдача | Ветка `feat/clothes-tagging`, краткий отчет, команды воспроизведения, видео до 4 минут и ссылка на конкретный коммит переданы организатору. |

Работа не считается законченной, если остался HTTP 501, вместо результатов используются заглушки, данные не попадают в PostgreSQL, отсутствует сравнение трех подходов или сообщается успех при ошибке сохранения. Пустой test, исключение неудобных ошибок из знаменателя и метрики только на удачных запросах не дают воспроизводимой оценки.

Приоритет — законченный основной сценарий и проверяемые решения. Дополнительные атрибуты, переключение пайплайнов и более сложная архитектура допустимы, но не компенсируют отсутствие основных требований. Фиксированного проходного accuracy до выпуска и проверки корпуса нет; ошибки модели нужно измерить и объяснить.
