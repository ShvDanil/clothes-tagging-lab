# Датасет

**Статус: source-v2 загружен и проверен, доступ исполнителю выдается отдельно.** Данные находятся в приватном бакете `clothes-tagging`, префиксе `prepared/source-v2/`. В наборе 996 товаров: 346 Zara, 400 Uniqlo и 250 Massimo Dutti. Validation/test — 797/199. Сохранены 8 481 уникальная фотография и 8 662 связи с галереями; в самостоятельных товарных папках находятся 8 533 файла фото, включая копии, используемые несколькими товарами. Целостность файлов и отсутствие пересечений split проверены.

## Источники и контрольная разметка

Ориентир объема — около 1 000 товаров; пригодные карточки не отбрасываются ради точного числа. Для каждого товара в `manifest.jsonl` назначается одно `primary_image_id` и путь к основному фото. API принимает 1–N фото одного товара и цветового варианта и возвращает один объединенный результат. `primary_image` остается опорным изображением; остальные ракурсы доступны в `images`. Для сравнения трех подходов зафиксируйте одинаковое правило выбора фото в пределах лимита API; использовать всю галерею не требуется.

Контрольная разметка строится **только по данным карточек магазинов**: категории, названия, выбранный цвет, явные характеристики и описания. Описания сохраняются дословно на исходном языке, с URL и контрольной суммой снимка источника. Дополнительные характеристики по фотографии организатор не придумывает и моделями не заполняет.

Категории и значения сопоставлены сокращенной таксономии Ximilar. Каждый известный признак содержит исходное поле, значение и правило сопоставления. Неоднозначное значение остается `unknown`; противоречащие друг другу категории и неподтвержденные соответствия карточки изображению откладываются. Детский раздел, наборы и multipack исключаются по сведениям источника.

Такие контрольные значения не являются проверенным по фотографии gold. Карточка может описывать скрытый признак, а фотография — показывать несколько вещей. Метрики отражают согласованность с данными магазина и должны сопровождаться описанием этого ограничения. Отсутствие признака в источнике не означает его отсутствия или нераспознаваемости на изображении.

## Состав и split

Разбиение validation/test — примерно 80/20 по целым группам с учетом категории и магазина. Одинаковые нормализованные названия внутри источника, явно связанные товары и совпадающие SHA-256 изображений объединены до split. Автоматическая оценка визуального сходства изображений при подготовке не применяется; неизвестные близкие варианты могут остаться. Training не требуется. Все три подхода сравниваются на всем test; обязательного малого среза нет.

Готового кода предобработки, вызовов моделей или оценки нет:

| Файл | Содержимое |
| --- | --- |
| `manifest.jsonl` | По одной строке на товар: ID, магазин, раздел, группа, split, пути и S3-ключи карточки и основного фото. |
| `products/<магазин>/<артикул>/item.json` | `retailer_data` — данные магазина; `mapping` — категория и признаки с доказательствами; `images` — файлы и все исходные связи с галереями. |
| `products/<магазин>/<артикул>/<sha256>.<формат>` | Фото рядом с JSON, исходные байты без преобразования. |
| `splits/validation.txt`, `splits/test.txt` | По одному ID основного изображения (SHA-256) в строке. |
| `splits/validation-products.txt`, `splits/test-products.txt` | ID товаров соответствующего split. |
| `report.json`, `release.json` | Количества, split, версии, происхождение данных и контрольные суммы. |

Внутри `item.json` имена фото относительны папке товара; пути в общем manifest относительны корню релиза. Для основных изображений используются `primary_image` в карточке и `primary_image_id` в manifest. Файлы split содержат те же SHA-256 ID.

Каждый файл `images` может иметь несколько `source_records`: это сохраняет все исходные роли, варианты, URL и подписи при совпадении изображения. В `captions.by_language` находятся дословные подписи магазина на полученных языках, в `captions.feature_text` — исходная подпись features при наличии. Русские подписи не переводились организатором. Связи с `variant_key=null` и неподтвержденным цветом относятся к общим фото; цвет выбранного варианта к ним автоматически не применяется. Поле `mapping.variant_key` задает вариант, к которому относятся контрольные значения.

Формат данных не навязывает схему вашего API. URL, название, описание, категория магазина и сами контрольные значения не передаются модели в качестве подсказок.

## Неизвестные и неприменимые значения

Для каждого поля используются `status` (`known`, `unknown`, `not_applicable`), `value` и происхождение. `value` при `known` — одно значение сокращенной таксономии.

- `unknown` в контрольных данных означает отсутствие однозначного значения в источнике. Ответ модели на таком поле нельзя автоматически считать ошибкой.
- Отсутствие упоминания рисунка не становится `Design=plain`, а отсутствие слова «капюшон» — `Hood=no hood`.
- `not_applicable` задается набором атрибутов категории. `Pattern` также неприменим при явно указанном однотонном дизайне; `plain` является значением `Design`.
- Необязательная `Subcategory` не входит в основное сравнение. Материал, бренд, цена и сезон не считаются обязательными визуальными эталонами.

## Загрузка из S3

Endpoint: `https://storage.yandexcloud.net`, регион: `ru-central1`, бакет: `clothes-tagging`, версия: `source-v2`, префикс: `prepared/source-v2/`. Доступ на чтение передается отдельно. Для выполнения задания не нужны права на запись или профиль владельца бакета.

Для работы с бакетом можно использовать и другие [поддерживаемые S3-инструменты](https://yandex.cloud/ru/docs/storage/tools/). Ниже приведен один воспроизводимый вариант скачивания; загрузка через консоль или другой клиент не меняет формат релиза.

Установите [AWS CLI](https://docs.aws.amazon.com/cli/latest/userguide/getting-started-install.html) и создайте локальный профиль с **выданными вам** данными доступа:

```bash
aws configure --profile clothes-dataset
```

При настройке укажите регион `ru-central1`, согласно [инструкции Yandex Cloud](https://yandex.cloud/ru/docs/storage/quickstart/quickstart-aws-cli). Остальные параметры и допустимый способ аутентификации уточняются вместе с доступом. Секреты вводите в настройку профиля, не в код, README или команды с буквальным ключом.

```bash
aws --profile clothes-dataset \
  --endpoint-url https://storage.yandexcloud.net \
  s3 ls 's3://clothes-tagging/prepared/source-v2/' --recursive

aws --profile clothes-dataset \
  --endpoint-url https://storage.yandexcloud.net \
  s3 sync 's3://clothes-tagging/prepared/source-v2/' ./data/releases/source-v2/
```

`data/releases/` игнорируется Git. После загрузки проверьте версию, количества и контрольные суммы по паспорту релиза. Способ проверки и подготовки данных для экспериментов реализуйте самостоятельно. Внутри сервиса поддержка S3 не обязательна: файл с диска передается в обычный multipart-запрос.

Если доступ анонимный или применяется другой способ выдачи, это будет явно указано. Не коммитьте конфигурацию профиля, ключи, временные подписанные URL и скачанные изображения. Публичность репозитория сама по себе не дает права распространять фотографии.
